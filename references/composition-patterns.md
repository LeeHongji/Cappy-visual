# 8 种构图与原创规则

单张选择一个结构，不混用太多。下列是表达方式，不是固定模板。

| 结构 | 适用内容 | 画面原则 |
| --- | --- | --- |
| Workflow 流程 | 输入、处理、输出、自动化 | 左输入、Cappy 在中间执行处理、右输出；橙色仅表示主流向。 |
| 系统局部 | 来源、过滤、数据库、agent 局部 | 只画 3–5 个核心模块，Cappy 参与一个关键动作，不铺满全系统。 |
| 前后对比 | 混乱到有序、手动到自动 | 两种可读状态，中间少量橙色关系；用同一物件的变化连接。 |
| 角色状态 | 信息焦虑、卡住、工具过多 | 2–4 个小状态，每个一个短标注，脸和姿态表达变化；动作与表情可更夸张，但保持键帽壳和短手脚。 |
| 概念隐喻 | 黑盒、内容生产、知识系统 | 一个主要怪物件，少量输入与输出，Cappy 执行核心物理动作。 |
| 方法分层 | 能力栈、系统层级、方法框架 | 一层层盒子或物件，Cappy 搬、搭、支撑；避免正式金字塔。 |
| 地图路线 | 想法到上线、用户路径、学习 | 一条弯曲路线和少量节点，Cappy 真正行进或铺路。 |
| 小漫画分镜 | 失败到成功、使用变化、吐槽 | 2–4 个松散小场景，各一个动作；不画密集格框和长对白。 |

## 发明隐喻

1. 抽象概念换成物理动作：卡住、漏掉、变重、分拣、沉淀、发酵、开门、折叠、拆包、回流。
2. 系统结构换成 1–2 个低科技物件：纸箱、抽屉、旧机器、漏斗、秤、邮筒、门、井、梯子、水管、线团、闸门、转盘、黑盒、打孔器、压面机、晾衣绳、怪工位。它们是外部道具，不把 Cappy 的身体变成这些物件。
3. 让 Cappy 承担动作，保留键帽外形。主题、物件与动作之间必须能解释，不能为了怪而怪。

## 不复刻

`assets/examples/` 只校准线条、留白、中文密度、颜色和参与方式。除非明确要求复刻某图，不照搬旧图的“物件 + 动作 + 布局 + 标注”组合。

原技能的传送带双断点、机器内拉判断杆、漏斗分流、切素材鱼、牵承接路径、拉三层信息源、喇叭搭桥开门、盖章工具箱、举牌看坑等案例，不能简单换头再用。Cappy 样例也受同样规则约束。

用户明确要求“把这张图里的角色换成 Cappy”时可保留目标构图和文字，用编辑模式替换角色，并让 Cappy 接手原动作。此时用户要求的构图保留优先于默认原创规则。
