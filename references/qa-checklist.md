# 生成后的 QA

每次生成或编辑后必须完成至少一轮实际看图的视觉审核，之后才能交付、用于 README 或发布。提示词写对、像素尺寸正确、白底比例达标，都不能代替视觉审核。

## 必须按这个顺序看图

1. 把用户原稿与当前成图并排对照；原稿决定 IP，不拿上一张生成图的错误当参考。
2. 看全图：主次、动作、留白、角色比例与含义。
3. 按原始分辨率逐个角色检查两只手、两只脚、连接处、道具接触和遮挡，将同一角色的两手对照原稿看手形与伸出幅度。必要时放大局部。多格图不能只抽查一个角色。
4. 缩到约 900px 和 360px 宽度再看识别度、主要动作与文字层级。
5. 为每张写具体结论。修复任何一处后，对新版本重新执行这轮审核。

## 肢体与物理关系：任一失败都要返工

- 可见手掌轮廓与连接清楚，被遮部分有具体遮挡者和成立的前后边界；没有断手、悬浮手、额外的手或不明黑块。不以“必须露出完整双手”作为通过条件。
- 两手沿用原稿同一套圆润连指形状，比例符合透视；操作手没有为了够到道具而异常伸长、膨大、排出一串指节或硬折手腕。放下道具后，这只手仍应像 Cappy 的手。
- 动作在短手可及范围内，掌面、接触点与身体重心配合；非操作手姿态自然。手脚数量正确但动作明显别扭，也需返工。
- 两脚有合理位置与支撑关系；被遮住的部分必须指出具体遮挡者，不能靠推测放行。
- 抓握、托举、按压、剪切等动作有可见接触：握住柄、托住底部或压到受力点，而不是“手在旁边就算参与”。明确能读出是哪种动作；关键接触被次要物件完全挡住、无法判断时，调整构图后复审。
- 物件在正确的前后层级，不能穿手、穿脸、切断键帽壳体，或一半在前一半在后。
- 顶面、前面、侧面与底边透视一致，键帽上窄下宽，不变成直壁方盒或独立头身。
- 不能用“手绘随意”“怪诞隐喻”“看起来可爱”豁免结构问题。原稿已有的表情变化可以保留。
- 修正肩臂熔合时，用清晰的轮廓转折和前后边界表达连接；不能用贯穿白缝把手从身体上剪断。

## 必过项

- 16:9 横版；用文件尺寸核对，不能靠感觉。允许栅格取整带来不超过 1 像素的高度差，例如 1672×941；明显比例错误优先重生成，不靠拉伸变形修正。
- 干净纯白底，没有米色、灰底、纸纹、噪点、阴影或渐变。
- Cappy 保持白色上窄下宽键帽、椭圆脸框、简笔黑眼嘴、短手短脚；三分之四视角有顶面/侧面。合理遮挡允许，但不能出现独立头身或黑豆体。
- Cappy 承担核心动作；移除它会失去动作执行者，不能只在边角看图。
- 一张只讲一个核心意思；主场景约占 40–60%，留白至少约 35%。
- 隐喻与当前内容成立，非默认复刻旧案例；用户明确要求改旧图时除外。
- 中文逐字比对请求词，通常 3–5 处、最多 5–8 处；无乱码或大段说明。
- 橙色只用于主路径/箭头，红色用于重点/问题/结果，蓝色用于补充/反馈/系统状态；不要求三种色每张都齐。
- 没有左上角类型标题、正式流程图、PPT 网格、商业插画或可爱海报。
- Cappy、道具与场景的黑色轮廓风格统一，符合原稿，略有手绘感；文字是轻手写批注。不要把角色与场景的极端粗细反差误当成默认风格，也不要让文字变成厚重标题字。
- 保存为独立可打开的项目图片，修改版不覆盖原始资产。

## 如何修正

| 问题 | 修正 |
| --- | --- |
| 角色黑豆化、白点眼、长腿化 | 加原稿身份参考重生成或局部换角色；白壳与椭圆脸是硬约束。 |
| 手形不统一、够物姿态别扭 | 先移近角色或道具、调整物件粗细与机位，再重画圆润短手；允许明确遮挡，不靠拉长手臂或强行露全双手解决。 |
| 角色装饰化、意思普通 | 重写核心动作，让 Cappy 亲自拉、推、接、拆或搭。 |
| 太复杂 | 删次要节点、箭头、背景；保留一个动作与 3–5 个短标注。 |
| 太可爱 | 去星星、爱心、服装和卖萌姿势；保留原稿眼嘴，强调认真做事。 |
| 太 PPT | 去标题、边框、整齐模块网格，用具体手绘物理场景。 |
| 像旧案例 | 换主物件和动作；不能只替换角色名字。 |
| 中文错字 | 窄范围局部编辑；错得多时减少标注后重生成。 |
| 底色或比例错误 | 明确纯白和 16:9 重生成。 |

去标题/改图后比对目标图：指定内容应改变，其他角色、动作、标注和结构保持。生成模型可能有局部漂移，漂移影响意思或身份时继续修正，不能声称逐像素不变。

每轮只修一个主要问题。重复尝试仍失败时如实说明并交付可用版本及限制，不能无限重试或宣称全部通过。

## 交付判断

至少记录下表。出现“无法确认”时按待修处理，不把它计入通过数量。

| 图片与版本 | 原稿对照 | 左右手与接触点 | 两脚与遮挡 | 壳体透视 | 中文/构图/清晰度 | 结论与下一步 |
| --- | --- | --- | --- | --- | --- | --- |
| 实际文件名 | 具体身份依据 | 每只手在哪里、实际怎样持物 | 支撑关系或明确遮挡者 | 是否符合原稿 | 实际观察 | 通过 / 返工 / 无法确认 |

README 封面也执行同一套角色与肢体审核；额外检查标题拼写、边距和缩小后的识别度。记录实际生成工具和真实像素尺寸，不声称工具未回显的具体模型，也不把放大图冒充原生高清封面。

先觉得有点怪，再迅速看懂关系；Cappy 能认出来，也在认真做事。不同主题的插图保持同一 IP，但不重复同一个道具和构图。
